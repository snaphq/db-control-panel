# MCP and agent surfaces

## MCP request path

`packages/site-kit/src/app/mcp/route.ts` (served by every site) authenticates
the request (unless the explicit local override is enabled), establishes an
async request context, and registers the site's toolsets from
`siteConfig.mcp` through `registerSiteTools` in `@repo/mcp-server`. `@repo/mcp-chatgpt` supplies
tool metadata, structured logging, context propagation, wrappers, and ChatGPT
submission helpers.

Keep the tool registry explicit. Tool names, annotations, widget metadata, and
admin authorization should be reviewed as an API contract; do not expose admin
tools through the public widget registration path.

The public transport accepts three bearer credential types, tried in order:
agent access JWTs issued by the `auth.md` flow, operator tokens (`opt_…`,
attributed through the operator request context), and OAuth MCP access tokens.
Retired personal account tokens (`cet_…`) are rejected with migration guidance.
The admin MCP transport lives on the backend (`apps/backend`, `/mcp`), accepts
only a backend admin session, and never accepts operator credentials. See
[Operator tokens](/architecture/operator-tokens) for scope, role, and activity
behavior.

## Administrative surfaces and tenant scope

Sites expose no admin pages or admin tools. The admin console and the admin
MCP endpoint live in `apps/backend`; see
[Backend admin portal](/architecture/backend-admin). The admin MCP endpoint
takes the tenant explicitly (`/mcp?tenant=<id>`) and scopes every admin tool
query to it; a site host, session, or role never authorizes it.

The legacy `payments` table is global and has no tenant foreign key. It is
therefore intentionally excluded from tenant-bound MCP tools and statistics;
payment views remain available only in the platform-wide backend console
until a tenant-keyed billing migration is reviewed and applied.

## Discovery surfaces

The app publishes:

- protected-resource and authorization-server metadata;
- OIDC wrapper metadata and the agent-auth JWKS;
- MCP server card and curated API catalog;
- agent-documentation index and per-document Markdown files. This is an
  application documentation feed, not MCP-importable skills: the server does
  not advertise `io.modelcontextprotocol/skills`, `skills/list`, `skills/get`,
  or `skill://` resources;
- `/auth.md`, `/llms.txt`, `/llms-full.txt`, robots, sitemap, and markdown
  negotiation for public content.

The product is MCP-only. A2A is intentionally not applicable to this
repository: there is no A2A Agent Card, task/message lifecycle, or A2A
endpoint. Do not describe the MCP server card or the application agent
registry as A2A support unless that protocol is separately designed and
implemented.

Tenant-bound discovery routes first resolve the request host and then derive
URLs from the validated request origin; static app-wide content may use the
shared `site-config` base URL helper. A catalog is intentionally curated:
admin, billing, and workspace-internal REST routes are not automatically
advertised to agents.

## Public markdown

`agent-discovery.ts` decides which public routes can negotiate
`Accept: text/markdown`. Protected app routes, admin pages, and raw API routes
must stay out of that allowlist. When the public docs source changes, update
the markdown index, WebMCP tool descriptions, sitemap, and catalog links in
the same change.
