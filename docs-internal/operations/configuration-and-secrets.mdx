# Configuration and secrets

`env.example` is the variable-name inventory. Shared local values live in the
root `.env.local`; `apps/backend/.env.local`, every `sites/*/.env.local`, and
`packages/database/.env.local` are symlinks to it. Each app's non-secret local
URL lives in its committed `.env.development` (`NEXT_PUBLIC_APP_URL`, which is
also the Better Auth base URL); never set it in the root `.env.local`, where
it would override every app. Deployment providers supply the same names
per project through their secret/configuration store.

## Groups

- Required: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BACKEND_ADMIN_EMAILS`,
  `BACKEND_SESSION_SECRET`; per app, `NEXT_PUBLIC_APP_URL`.
- Billing: Stripe secret, webhook, and publishable values.
- External services: PostHog, Resend, Inngest, and provider keys.
- Security: integration encryption keys, agent-auth signing/TTL values,
  and rate-limit credentials.
- Tenant/app presentation: default tenant and public app URL/name values.

## Name inventory

Use `env.example` as the complete, current inventory. The main names are:

- Core: `DATABASE_URL`, `NEXT_PUBLIC_APP_URL` (per app).
- Backend admin: `BACKEND_ADMIN_EMAILS`, `BACKEND_SESSION_SECRET`.
- Site identity: `SITE_TENANT_ID` is not configured by hand; each site's
  `next.config.ts` sets it from `site.config.ts`.
- Auth: `BETTER_AUTH_SECRET`, `PASSKEY_RP_ID`,
  `NEXT_PUBLIC_GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
  `NEXT_PUBLIC_GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`,
  `ADMIN_EMAIL_DOMAINS`.
- Billing and delivery: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`,
  `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`, `RESEND_API_KEY`,
  `RESEND_FROM_EMAIL`, `RESEND_FROM_NAME`, `STRIPE_SCHEMA`, `PG_POOL_MAX`.
- Analytics and limits: `NEXT_PUBLIC_POSTHOG_KEY`, `NEXT_PUBLIC_POSTHOG_HOST`,
  `POSTHOG_PROJECT_API_KEY`, `POSTHOG_PERSONAL_API_KEY`, `POSTHOG_PROJECT_ID`,
  `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `AXIOM_TOKEN`,
  `AXIOM_DATASET`, `AXIOM_OPERATOR_DATASET` (optional; falls back to
  `AXIOM_DATASET` for operator activity).
- Agent auth: `AGENT_AUTH_ENABLED`, `AGENT_AUTH_PRIVATE_KEY`,
  `AGENT_AUTH_KEY_ID`, `AGENT_AUTH_ASSERTION_TTL_DAYS`,
  `AGENT_AUTH_ACCESS_TOKEN_TTL`, `AGENT_AUTH_REGISTRATION_TTL_DAYS`,
  `ID_JAG_MAX_AUTH_AGE_SECONDS`, `MCP_REQUIRE_AUTH`.
- Integrations and storage: `INTEGRATION_ENCRYPTION_KEY`,
  `MCP_PROXY_ALLOWED_HOSTS`, `AI_PROVIDER_ALLOWED_HOSTS`,
  `OBJECT_STORAGE_PROVIDER`, `BLOB_READ_WRITE_TOKEN`, `S3_BUCKET`,
  `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_ENDPOINT`,
  `CHATGPT_APP_CATEGORY`, `CHATGPT_APP_DESCRIPTION`,
  `CHATGPT_APP_DISPLAY_NAME`, `CHATGPT_APP_SUBTITLE`.
- Tenant presentation: `DEFAULT_TENANT_ID`, `DEFAULT_TENANT_NAME`,
  `DEFAULT_TENANT_SLUG`, `DEFAULT_TENANT_PLATFORM_NAME`,
  `DEFAULT_TENANT_DOMAIN`, `DEFAULT_TENANT_SUPPORT_EMAIL`,
  `DEFAULT_TENANT_LOGO_URL`, `DEFAULT_TENANT_FAVICON_URL`,
  `NEXT_PUBLIC_APP_NAME`, `SUPPORT_EMAIL`.
- AI and jobs: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `AI_DEFAULT_MODEL`,
  `INNGEST_EVENT_KEY`, `INNGEST_SIGNING_KEY`, `INNGEST_DEV`,
  `INNGEST_BASE_URL`.

Do not copy values from `.env.local` into docs, logs, screenshots, or test
fixtures. Public browser variables must be deliberately prefixed and should
never be used as a substitute for server-side credentials.

## Rotation and failure handling

Document a rotation/migration before changing encryption or signing keys. When
an optional service is not configured, the code should follow its documented
local fallback or fail with a contextual error; do not silently invent a
production fallback.
