# Database migrations

The Drizzle schema in `packages/database/src` (the files listed in
`packages/database/drizzle.config.ts`) is the only schema source of truth.
There are no hand-written SQL migrations: tables, columns, foreign keys,
indexes (including partial unique indexes), and constraints are declared in
Drizzle.

A fresh database is created from the schema, then seeded with the default
tenant and admin:

```bash
bun run db:push
bun run db:seed
```

For shared environments that need a reviewed migration history:

```bash
bun run db:generate
bun run db:migrate
```

Generated output under `packages/database/drizzle` is local and gitignored.

## Review checklist

1. Confirm the schema change is owned by the correct schema module and remains
   tenant-safe.
2. Inspect generated SQL, indexes, constraints, and data backfill behavior.
3. Check the migration against a disposable non-empty database.
4. Apply it through the configured deployment process and verify a real query
   path, not only the migration journal.
5. Record rollback or forward-fix steps before production application.

Seeds are explicit scripts. They must not be silently invoked by a normal app
build or request.
