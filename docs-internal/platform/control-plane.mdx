# Control plane

`apps/control-plane` replaces the closed-source part of Neon's cloud and the
Turso platform API. It is one TypeScript codebase run in four modes (see
[Platform architecture](/platform/architecture)). The console never talks to
the data plane directly; it calls this service's API.

## Stack

- Node 22 at runtime (Bun is used only for installs and scripts), ES modules,
  TypeScript compiled with `tsc` into `dist/`.
- Hono with `@hono/node-server` for HTTP, Zod for request and env
  validation, Drizzle ORM with the `postgres` driver, pg-boss for the
  operations queue, `@kubernetes/client-node` for pods and routes, and
  `node:crypto` for Ed25519 and SCRAM (no extra crypto dependency).
- Vitest for unit tests of every pure module. Files stay under 600 lines.

## Source layout

```text
apps/control-plane/src/
  index.ts              mode switch (ALLOYDB_MODE)
  config.ts             env schema
  db/                   Drizzle schema, client, migrations
  crypto/               ed25519 JWT signing, SCRAM-SHA-256 secrets, ids
  neon/                 storage-controller client, compute spec builder,
                        compute pod manifests, wake/suspend logic
  libsql/               sqld admin client, routes, token minting
  data-api/             PostgREST bootstrap SQL, gateway proxy
  modes/                api, neon-glue, worker, data-api-gateway servers
  operations/           operation runner and step definitions
```

## Data model

Database `control_plane`. Ids are prefixed strings generated by the control
plane (`proj_`, `br_`, `ep_`, …) except Neon tenant and timeline ids, which
are 32-hex values as Neon requires.

| Table | Key columns |
| --- | --- |
| `neon_project` | id, console_project_id, console_org_id, name, tenant_id, pg_version, history_retention_seconds, created_at, deleted_at |
| `branch` | id, project_id, name, timeline_id, parent_branch_id, parent_lsn, safekeepers (jsonb: generation + `[{id, hostname}]`), is_default |
| `endpoint` | id (`ep-<word>-<word>-<n>`), branch_id, type (`read_write`, `read_only`), compute_size, suspend_timeout_seconds, state (`idle`, `starting`, `running`, `suspending`), pod_name, pod_ip, last_active_at |
| `role` | id, branch_id, name, scram_secret (never the plaintext password) |
| `database` | id, branch_id, name, owner_role, data_api_enabled |
| `libsql_database` | id, console_project_id, name, namespace, node_id, state, size_limit_bytes |
| `node` | id (`ALLOYDB_NODE_ID`), name, tailscale_ip, zone, roles, capacity (jsonb), registered_pageserver, registered_safekeepers |
| `operation` | id, target_type, target_id, action, status (`scheduling`, `running`, `finished`, `failed`, `cancelled`), failures_count, error, created_at, finished_at |
| `usage_event` | id, project_id, kind, value, idempotency_key (unique), recorded_at |

The console stores only its own `project.id` and receives these ids back.

## Operations

Mutations write desired state and an `operation` row in one transaction,
enqueue a pg-boss job, and return `202` with the operation. A project with an
operation in `scheduling` or `running` rejects new mutations with `423`.
Every step is idempotent and safe to retry; the runner stores progress on the
operation row. Actions:

`project.create`, `project.delete`, `branch.create`, `branch.delete`,
`endpoint.start`, `endpoint.suspend`, `endpoint.update`,
`role.reset_password`, `database.create`, `database.delete`,
`data_api.enable`, `data_api.disable`, `libsql.create`, `libsql.delete`,
`libsql.fork`.

## Neon flows

**Create project.** `POST /v1/tenant` on the storage controller with a new
tenant id, then `POST /v1/tenant/:id/timeline` with `{new_timeline_id,
pg_version: 17}`. The response's `safekeepers` field (present because of
`--timelines-onto-safekeepers`) is stored on the branch. Create the default
branch, a `read_write` endpoint, the owner role, and database `neondb`.

**Create branch.** `POST /v1/tenant/:id/timeline` with `{new_timeline_id,
ancestor_timeline_id, ancestor_start_lsn?}`; point-in-time branches pass the
LSN.

**Compute spec** (`GET /compute/api/v2/computes/:id/spec`, called by
compute_ctl with a `tenantendpoint`-style bearer token). Returns
`{status: "attached", spec, compute_ctl_config: {jwks}}`:

- `format_version: 1.0`, `suspend_timeout_seconds`, `cluster.roles` (name +
  SCRAM secret), `cluster.databases`, `cluster.settings` with the base GUCs
  (`wal_level=logical`, `synchronous_standby_names=walproposer`,
  `shared_preload_libraries=neon,pg_cron,pg_stat_statements`,
  `password_encryption=scram-sha-256`, `listen_addresses=*`, `port=5432`,
  `max_replication_write_lag`, `max_replication_flush_lag`, memory settings
  from the compute size).
- `tenant_id`, `timeline_id`, `project_id`, `branch_id`, `endpoint_id`,
  `mode` (`Primary` for read-write).
- `pageserver_connection_info` built from the controller's
  `GET /debug/v1/tenant/:id/locate` response, mirroring
  `tenant_locate_response_to_conn_info` in Neon's `control_plane/src/endpoint.rs`.
- `safekeeper_connstrings` and `safekeepers_generation` from the branch row.
- `storage_auth_token`: a `tenant`-scoped JWT for that tenant.

**Wake** (`GET /proxy/wake_compute?endpointish=`). Strip a `-pooler` suffix
to find the endpoint. If no pod is running, create `compute-<id>`, then poll
compute_ctl `GET :3080/status` (JWT with `aud: ["compute"]`, `scope:
"compute_ctl:admin"`) until `Running`. Return `{address:
"<podIP>:5432"}` (or `:6432` for `-pooler`) with `aux: {endpoint_id,
project_id, branch_id, compute_id, cold_start_info}`. Concurrent wakes for one
endpoint share a single in-flight start.

**Access control** (`GET /proxy/get_endpoint_access_control?endpointish=&role=`)
returns `{role_secret}` (empty when the role does not exist) and
`allowed_ips` when the project restricts them.

**Suspend.** The worker polls every running compute's `/status`; when
`last_active` is older than the endpoint's `suspend_timeout_seconds`
(default 300, `0` = never), it calls `POST /terminate?mode=fast` and deletes
the pod.

**Storage-controller hooks.** `PUT /storcon/notify-attach` and
`PUT /storcon/notify-safekeepers` (bearer `CONTROL_PLANE_JWT_TOKEN`) update
stored placement and tell a running compute to reload its spec; they return
200 only after that, 503 when the compute could not be reached.

**Registration.** On start and on every node change, the worker registers
safekeepers (`POST /control/v1/safekeeper/:id` then scheduling policy
`Active`) and records pageservers from `GET /control/v1/node`.

## Data API

Enabling it for a database: run bootstrap SQL as the owner role (create
`authenticator` LOGIN NOINHERIT with a generated password, `anonymous` and
`authenticated` NOLOGIN, grants, `GRANT anonymous, authenticated TO
authenticator`), add a `postgrest-<db>` container to the endpoint's pod spec,
and restart the compute. The gateway serves
`https://ep-<id>.apirest.alloydb.net/<db>/rest/v1/…`: it wakes the endpoint
(same in-process path as the proxy wake), strips `/<db>/rest/v1`, and
forwards to that container. JWTs are verified by PostgREST against the
project's JWKS (`PGRST_JWT_SECRET`), with `PGRST_DB_ANON_ROLE=anonymous`.

## libSQL flows

**Create.** Pick the `libsql` node with the most free share, call its admin
API `POST /v1/namespaces/<ns>/create` (namespace `<db>-<team>`), create the
node's Service and EndpointSlice if missing, and create an `IngressRoute`
for `<ns>.lite.alloydb.net`. **Tokens** are EdDSA JWTs signed with the
`libsql-jwt-signing` key, claims `{p: {rw: {ns: [<ns>]}}}` or `{p: {ro: …}}`,
with an expiry the user picks. **Fork** uses
`POST /v1/namespaces/<ns>/fork/<to>` with an optional timestamp.
**Delete** removes the namespace (optionally keeping the backup) and its route.

## Public API (mode `api`)

All routes require `Authorization: Bearer <ALLOYDB_API_TOKEN>` (held by the
console's server code) plus `X-AlloyDB-Org` and `X-AlloyDB-Project` headers
that the console sets after its own membership checks. Shapes follow Neon's
v2 API where one exists:

`/v1/projects` · `/v1/projects/:id` · `/v1/projects/:id/branches[/:branch]` ·
`/v1/projects/:id/endpoints[/:endpoint][/start|/suspend]` ·
`/v1/projects/:id/branches/:branch/{roles,databases}` ·
`/v1/projects/:id/branches/:branch/roles/:role/reset_password` ·
`/v1/projects/:id/branches/:branch/databases/:db/data_api` ·
`/v1/libsql/databases[/:id][/tokens|/fork]` · `/v1/operations/:id`.
