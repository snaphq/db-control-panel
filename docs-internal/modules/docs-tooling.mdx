# Documentation tooling

The hand-maintained documentation sources are the root `docs-public/` and
`docs-internal/` trees. Their `docs.json` files own Mintlify navigation. The
public tree is also consumed by the app's Fumadocs loader when the in-app
`/docs` surface in `packages/site-kit/src/app/docs/` is retained, making it a
generated view rather than a second content source.

## Ownership

- Edit content in the appropriate root tree.
- Keep navigation slugs in `docs.json` synchronized with files.
- Keep `/auth.md` generated from `packages/site-kit/src/app/auth.md/route.ts` and
  update the public/internal agent-auth pages when its contract changes.
- Do not add `apps/*/docs`, `packages/*/docs`, or another generic `docs/`
  directory.

## Validation

Use the public/internal preview and broken-link commands, the staged path policy,
and the coverage checker. Source-path references in internal pages should be
covered by `docs-internal/coverage.json` and verified at the same commit as the
documentation change.

## Site-specific docs

Docs about one site live in `docs-public/<site>/` and `docs-internal/<site>/`,
where `<site>` is the site's short name (`alloydb.console` for `sites/net.alloydb.console`), and
appear under the **Sites** tab of each Mintlify site. `check:doc-coverage`
enforces it: an entry whose sources are all under one `sites/<folder>/` must
point at a page in that site's folder. Each Next.js site's `source.config.ts`
excludes the other sites' folders, so its `/docs` shows shared pages plus its
own. `rename-site.ts` moves these folders when a site is renamed.
