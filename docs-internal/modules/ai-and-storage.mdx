# AI and object storage modules

## `@repo/ai`

`packages/ai/src/client.ts` owns the OpenAI-compatible client and default model
selection. `run.ts` exposes query, metadata, and streaming helpers. Keep API
keys and optional `OPENAI_BASE_URL` values server-side; callers should use the
package exports rather than instantiating a provider in a route. Runtime calls
validate HTTPS, public DNS resolution, redirect behavior, response size, and
the `AI_PROVIDER_ALLOWED_HOSTS` production allowlist before sending a stored
key to a custom OpenAI-compatible endpoint.

## `@repo/object-storage`

`createStorageClient` selects a provider behind the `StorageClient` interface.
The current providers are Vercel Blob and an S3-compatible implementation. The
interface covers upload, list, signed access, metadata, and ACL options.

App routes under `apps/next-app/src/app/api/storage` and integration code should
not depend on provider-specific return shapes. Provider selection and keys are
configuration concerns; the setup workflow may remove object-storage values
when a provider is disabled.

## Change and verification rules

- Preserve the interface when adding a provider and add a provider-focused
  test/fixture.
- Never log signed URLs, access keys, or uploaded private content.
- Exercise upload, list, signed access, and failure behavior against a
  disposable bucket before enabling a new provider in production.
