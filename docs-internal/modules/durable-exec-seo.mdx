# Durable execution and SEO/AIEO

`@repo/durable-exec` owns the Inngest client, durable event types, function
registration, billing jobs, and SEO/AIEO workers. The Next.js handler at
`apps/backend/src/app/api/inngest/route.ts` exposes the registered functions.

## Function groups

- Billing: trial expiration, pending-organization cleanup, and referral-window
  processing.
- SEO/AIEO: prompt/rank snapshots, competitor rollups, AI-engine inference,
  GSC synchronization, PostHog referrer rollups, secret validation, and
  budget/sentiment parsing.

The AIEO engine registry isolates provider-specific clients (Claude, Gemini,
Google AIO, OpenAI, Perplexity). DataForSEO and Google Search Console adapters
live beside the functions. Secrets are encrypted and masked through the AIEO
secret store; fallback provider keys are configuration, not documentation
examples.

## Reliability rules

- Assume Inngest delivery can retry; use stable event identifiers and
  idempotent writes.
- Keep expensive provider calls behind the function boundary and enforce the
  configured budget before dispatch.
- Record enough status/error context for operator recovery without logging
  secrets or full provider responses.
- Test the handler and a representative non-empty job path when changing a
  schema or function registration.
