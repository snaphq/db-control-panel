# Database package

`@repo/database` is the shared persistence boundary. It exports the Drizzle
client, core/application schemas, agent and agent-auth schemas, analytics and
SEO schemas, tenant helpers, admin DAL, SEO DAL, and selected Drizzle
operators.

## Source groups

- `schema.ts`, `schema-ext.ts`, `schema-operators.ts`, and
  `schema-plan-tier.ts`: core and billing
  application data.
- `schema-tenant.ts`: tenants, domains, and organization relationships.
- `schema-agents.ts` and `schema-agent-auth.ts`: agent records, registrations,
  claims, tokens, delegations, replay cache, and audit events.
- `schema-analytics.ts` and `dal/*`: analytics snapshots, series, and query
  helpers.
- `schema-seo.ts` and `dal/seo/*`: SEO/AIEO tracking data and accessors.

## Query rules

Keep SQL and result-shape policy in the database package or its owning DAL.
Routes should validate authorization and call a DAL/package function rather
than duplicating query logic. Use the shared `db()` client and preserve tenant
filters on every tenant-scoped query.

## Schema changes

Generate and review Drizzle migrations for shared environments. A migration
journal entry is not sufficient evidence: exercise a non-empty query path after
applying it and verify indexes/constraints used by the feature.
